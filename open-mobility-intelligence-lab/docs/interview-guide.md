# 面試展示指引

## 一句話介紹

「我用紐約市公開的 409 萬筆計程車行程，從原始檔清理、SQL 聚合、驗證，到做成一個可以在瀏覽器操作的 3D 分析與情境模擬平台，全部用開源工具，成本為零。」

## 三分鐘展示流程

1. **3D Explorer（40 秒）**：按下播放，讓 24 小時需求柱起伏。點選 JFK Airport，說明右側的需求曲線與主要目的地。提一句：流向動畫是示意，因為官方資料只有區域沒有 GPS，介面上有標示。
2. **Analytics（40 秒）**：切到 Weekends，指出深夜需求高於平日。把滑鼠移到 KPI 的 ƒ，說明每個數字都能追溯公式。
3. **What-if（40 秒）**：點 Combined 情境，說明三個槓桿是相乘而非相加（減量 61%，不是 8% + 14% + 51% = 73%）。指出龍捲風圖顯示排放係數的影響最大。
4. **Data Engineering（40 秒）**：說明 11 條規則逐條記錄排除筆數、18 項驗證、DuckDB 與 NumPy 交叉比對。打開 SQL 分頁展示 `GROUPING SETS`。
5. **Behind the Model（20 秒）**：資料分類表與限制清單。

## 可能被問到的問題

**為什麼排除 5.25% 的資料？**
每條規則都對應一種明確的資料錯誤，例如下車早於上車、里程為零。門檻集中在設定檔，排除筆數逐條公開。

**怎麼確定數字是對的？**
三層：SQL 聚合與清理表對帳、NumPy 獨立重算、前端測試再把已發布的 JSON 互相對帳。

**空車比例 40% 從哪來？**
是假設。TLC 資料沒有空車里程，所以做成可調參數，並用敏感度分析顯示它的影響。

**流向動畫是真實軌跡嗎？**
不是。粒子數量依真實 OD 量分配，路徑是區域標記點之間的示意弧線。

**為什麼不用後端？**
資料每月更新一次，預先聚合後只有 1 MB，靜態檔案更快、免費、沒有維運。

**AI 在開發中扮演什麼角色？**
用 Claude Code 協助撰寫與測試程式。資料選擇、清理門檻、模型假設與邊界由我決定並驗證，每個數字都有測試或對帳支撐。

## 展示前檢查

- 用桌機或筆電的 Chrome 開啟，確認 3D 地圖流暢。
- 確認網路可連 `tiles.openfreemap.org`，否則底圖不會顯示。
- 先自己走一遍流程，確認要點選的區域位置。
